# Package catalog

Everything a full `inv setup` installs on a workstation, in one table. This is the answer to "what
do I actually get" — [How it works](configuration.md) is the answer to "how", and
[apt_packages.md](apt_packages.md) explains the install _methods_ the `Method` column names.

The table is generated from `setup.toml`, which is the single declaration of what this repo
installs. It is not hand-maintained: `inv catalog.render-packages` rewrites it, and a unit test
fails if the committed table has drifted from `setup.toml`, so a package cannot be added without the
catalog following. Each row's text is the first sentence of that entry's `description`; the rest of
the description, and every install detail, stays in `setup.toml`.

**Reading the columns:**

- **Tags** decide what a given machine gets. Seven of them actually gate installation — `gui`,
  `desktop`, `gnome`, `workstation`, `corporate`, `ide`, `windows-native` — and `PULSE_EXCLUDE_TAGS`
  is how a headless server, a WSL distro or a dev container opts out of a whole class at once. See
  [How it works](configuration.md) for the rest, and [dev-container.md](dev-container.md) for the
  exclusion set a container uses.
- **Method** is how the thing is installed, not what it is: `apt` from Ubuntu's own archive,
  `apt-repo` from a third-party one, `deb-github`/`deb-url` from a release artifact, `uv-tool` for a
  PyPI-distributed CLI, `archive`/`binary`/`script` for upstream tarballs and install scripts, `nvm`
  for node, `gnome-extension`, and `zsh`/`wrapper-script` for entries that write config or a helper
  rather than installing a program.

Two kinds of `setup.toml` entry are deliberately absent: those disabled by default, since no machine
installs them, and the one entry that installs nothing at all (it exists to carry a permission
grant).
